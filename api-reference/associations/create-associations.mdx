---
title: 'Create Associations'
api: 'POST /api/v1/associations'
description: 'Batch create contact-company, contact-account, and contact-deal relationships'
---

## Request Body

<ParamField body="providerKey" type="string" required>
  Integration provider key (e.g. `hubspot`, `salesforce`). Defaults to `"api"` if not provided.
</ParamField>

<ParamField body="associations" type="array" required>
  Array of association objects to create
  
  <Expandable title="Association Object">
    <ParamField body="contactId" type="string">
      Internal UUID of the contact (bypasses mapping lookup; optional if `externalContactId` provided)
    </ParamField>

    <ParamField body="externalContactId" type="string">
      External ID of the contact (via integration mapping; optional if `contactId` provided)
    </ParamField>

    <ParamField body="companyId" type="string">
      Internal UUID of the company (bypasses mapping lookup; optional if `externalCompanyId` provided)
    </ParamField>

    <ParamField body="externalCompanyId" type="string">
      External ID of the company (creates `customer_company`; optional if `companyId` provided)
    </ParamField>

    <ParamField body="accountId" type="string">
      Internal UUID of the account (bypasses mapping lookup and auto-resolves company; optional if `externalAccountId` provided)
    </ParamField>

    <ParamField body="externalAccountId" type="string">
      External ID of the account (creates `contact_account` and auto-resolves company; optional if `accountId` provided)
    </ParamField>

<ParamField body="relation" type="string" default="employee">
  Relationship type. One of: `employee`, `consultant`, `contractor`, `partner`, `agency`, `other`. Invalid values silently default to `employee`.
</ParamField>

<ParamField body="isPrimary" type="boolean" default="false">
  Is primary company for contact. Forced to `false` for account-based associations.
</ParamField>

    <ParamField body="role" type="string">
      Role for the contact_account association
    </ParamField>

    <ParamField body="dealId" type="string">
      Internal UUID of the deal (bypasses mapping lookup; optional if `externalDealId` provided)
    </ParamField>

    <ParamField body="externalDealId" type="string">
      External ID of the deal (creates `deal_contact`; optional if `dealId` provided)
    </ParamField>

<ParamField body="dealRole" type="string" default="unknown">
  Role for the deal_contact association. One of: `decision_maker`, `economic_buyer`, `champion`, `influencer`, `user`, `stakeholder`, `admin`, `other`, `unknown`. Invalid values silently default to `unknown`.
</ParamField>
  </Expandable>
</ParamField>

## Validation Rules

1. **Contact Identifier:** Must provide either `contactId` OR `externalContactId`
2. **Company/Account/Deal Identifier:** Must provide at least one of:
   - `companyId` or `externalCompanyId` (for company-only associations)
   - `accountId` or `externalAccountId` (for account-based associations)
   - `dealId` or `externalDealId` (for deal-based associations)
   - Any combination of the above

## Association Flows

| Flow | Required Fields | Creates |
|------|----------------|---------|
| **Company-only** | contactId/externalContactId + companyId/externalCompanyId | `customer_company` |
| **Account-based** | contactId/externalContactId + accountId/externalAccountId | `contact_account`, `customer_company` (from account.companyId) |
| **Account + Company** | contactId/externalContactId + accountId/externalAccountId + companyId/externalCompanyId | `contact_account`, `customer_company` (for both companies) |
| **Deal-based** | contactId/externalContactId + dealId/externalDealId | `deal_contact`, `interaction_deal`, `customer_company` (from deal.companyId) |
| **Deal + Account** | contactId/externalContactId + dealId/externalDealId + accountId/externalAccountId | `deal_contact`, `interaction_deal`, `contact_account`, `customer_company` (for both deal and account companies) |

## Example Request

```bash
curl -X POST https://api.arali.ai/api/v1/associations \
  -H "Authorization: Api-Key YOUR_STATIC_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "providerKey": "hubspot",
    "associations": [
      {
        "externalContactId": "contact_12345",
        "externalCompanyId": "company_67890",
        "relation": "employee",
        "isPrimary": true
      },
      {
        "externalContactId": "contact_12345",
        "externalAccountId": "acc_abc123",
        "role": "decision_maker"
      },
      {
        "externalContactId": "contact_12345",
        "externalDealId": "deal_xyz789",
        "dealRole": "champion",
        "isPrimary": true
      }
    ]
  }'
```

## Response

<ResponseField name="status" type="string">
  Operation status. Always `"success"` for a completed batch request (individual failures are in `results`)
</ResponseField>

<ResponseField name="summary" type="object">
  <Expandable title="Summary Object">
    <ResponseField name="total" type="integer">Total associations processed</ResponseField>
    <ResponseField name="successful" type="integer">Successfully created</ResponseField>
    <ResponseField name="skipped" type="integer">Skipped (e.g. missing entity)</ResponseField>
    <ResponseField name="failed" type="integer">Failed</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="processingTimeMs" type="integer">
  Time taken to process the batch in milliseconds
</ResponseField>

<ResponseField name="results" type="array">
  Array of result objects. Each object contains:
  - `status`: `"success"`, `"skipped"`, or `"error"`
  - `flow`: The association flow that was used. One of: `company_direct`, `account_based`, `deal_direct`, `deal_and_account`
  - Additional fields depending on the outcome
</ResponseField>
