## Overview

Ingest a meeting recording URL. The API will create a completed meeting, upload the recording to R2, transcribe it, and optionally run analysis.

## Request Body

You can provide recordings in one of three formats:

**Format 1 — Single recording:**
<ParamField body="recordingUrl" type="string">
  URL to a single recording
</ParamField>

**Format 2 — Multiple recordings:**
<ParamField body="recordingUrls" type="array">
  Array of recording URLs
</ParamField>

**Format 3 — Batch with metadata (preferred):**
<ParamField body="recordings" type="array">
  Array of objects with per-item overrides. Each item supports:
  
  - `recordingUrl` (string) — URL to the recording
  - `title` (string) — Meeting title for this item
  - `externalMeetingId` (string) — External meeting ID for upsert
  - `metadata` (object) — Additional metadata. Supports `metadata.force` (boolean) to force re-ingestion.
  - `transcript` (string) — Per-item transcript (URL or plain text)
  - `force` (boolean) — Per-item force re-ingestion (delete and recreate if meeting already exists)
  - `forceAnalyze` (boolean) — Per-item force re-analysis
  - `createTranscript` (boolean) — Per-item transcript creation override
  - `uploadToR2` (boolean) — Per-item R2 upload override
  - `skipEmail` (boolean) — Per-item email skip override
  - `skipNotifications` (boolean) — Per-item notifications skip override
  - `skipInsightsEmbed` (boolean) — Per-item insights embed skip override
  - `enqueueAnalyze` (boolean) — Per-item metadata analyze job queue override
  - `meetingType` (string) — Per-item meeting type for analyze job
</ParamField>

### Per-Item Overrides

All top-level boolean and string fields also work as per-item overrides inside each `recordings[]` item. The top-level value serves as the fallback default when a per-item value is not specified.

The following fields are commonly overridden per-item:
- `title`, `externalMeetingId`, `metadata`
- `transcript`, `createTranscript`, `uploadToR2`
- `skipEmail`, `skipNotifications`, `skipInsightsEmbed`
- `force`, `forceAnalyze`
- `enqueueAnalyze`, `meetingType`

**Note:** `force` is **not** a top-level field. It only works inside `recordings[]` items or as `recordings[].metadata.force`.

## Job Flow

1. **Transcript creation** — If `createTranscript` is true, the system attempts to generate a transcript from the recording (or uses the provided `transcript`).
2. **Pre-analysis** — A `metadata.preanalyze` job is queued only when transcript creation succeeds.
3. **Analysis** — A `metadata.analyze` job is queued after preanalysis completes, but only when `enqueueAnalyze` is true.

## Response

### HTTP Status Codes

- `201 Created` — Normal successful ingestion
- `200 OK` — Returned when `waitForTranscript=true` and transcription has completed before the response is sent

## Example Request

```bash
curl -X POST https://api.arali.ai/api/v1/recordings/ingest \
  -H "Authorization: Api-Key YOUR_STATIC_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "recordingUrl": "https://recordings.example.com/meeting_123.mp4",
    "title": "Weekly Team Sync",
    "participantEmails": ["john@example.com", "jane@example.com"],
    "hostEmail": "john@example.com",
    "scheduledStartAt": "2024-01-20T10:00:00Z",
    "scheduledEndAt": "2024-01-20T11:00:00Z",
    "channel": "zoom"
  }'
```
