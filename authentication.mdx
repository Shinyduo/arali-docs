## Overview

All Arali API endpoints require authentication via either JWT bearer tokens or static API keys. Pass credentials in the `Authorization` header of every request.

```bash
Authorization: Bearer <JWT>
Authorization: Api-Key <static_key>
```

## Authentication Context

- `Bearer <JWT>`: `enterpriseId` is read from JWT claims (`scopes` claim is optional).
- `Api-Key <static_key>`: `enterpriseId` and `scopes` are read from your public API key record.

## Error Responses

### 401 Unauthorized

Returned when credentials are missing or invalid.

```json
{
  "error": "Invalid token"
}
```

<Warning>
  If you receive a 401 error, check that:
  - Your credentials are correctly formatted
  - The API key has not expired or been revoked
  - There are no extra spaces or characters
</Warning>

### 403 Forbidden

Returned when the credential lacks the required scope for the operation.

```json
{
  "error": "Insufficient permissions. Required scope: companies:write"
}
```

<Tip>
  If you receive a 403 error, you'll need to generate a new API key with the required scopes.
</Tip>

## Security Best Practices

<CardGroup cols={2}>
  <Card title="Keep Credentials Secret" icon="shield">
    Never expose API keys or JWTs in client-side code, public repositories, or logs.
  </Card>
  <Card title="Use Minimal Scopes" icon="minimize">
    Only request the scopes you actually need. This limits potential damage if a key is compromised.
  </Card>
  <Card title="Rotate Regularly" icon="rotate">
    Rotate API keys periodically, especially if team members leave or credentials may have been exposed.
  </Card>
  <Card title="Use Environment Variables" icon="terminal">
    Store API keys and JWTs in environment variables rather than hardcoding them in your application.
  </Card>
</CardGroup>

## Example: Validate Authentication

```bash
# JWT
curl -X GET 'https://api.arali.ai/api/v1/companies' \
  -H 'Authorization: Bearer YOUR_JWT'

# Static API Key
curl -X GET 'https://api.arali.ai/api/v1/companies' \
  -H 'Authorization: Api-Key YOUR_STATIC_KEY'
```

A successful response indicates your credentials are valid and include the `companies:read` scope.
